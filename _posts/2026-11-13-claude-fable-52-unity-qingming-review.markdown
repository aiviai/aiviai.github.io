上次测 Claude Fable 5.2，我已经试过复刻《清明上河图》。场景能走进去，也有船和街市，但和原画放在一起看，建筑结构、人物特点和整体画风，还是有很明显的距离。

所以这次，我又把虹桥这一段交给了它。工具换成 **Claude Code，推理级别开 High**，并明确要求使用 Unity 3D 游戏引擎。我想看看，它能不能把这幅画里那些挤在一起的建筑、人物和船只，做成一个更接近原画、可以自由探索的场景。

结果最值得看的，是船过桥那一段。桅杆慢慢放倒，绳索、拉绳的人、指挥的人和掌握船只方向的人，都能靠近观察。沿着河岸继续走，还能看到店铺、抬轿子的人，听到流水、鸟叫和驴叫。下面按这次的探索路线聊一聊。

## 这次用的模型和测试条件

Claude Fable 5.2 于 2026 年 11 月 9 日发布。按当前[官方模型文档](https://platform.claude.com/docs/en/models/fable-5-2/overview)，它支持 100 万 token 上下文、最大 12.8 万 token 输出，标准 API 价格为每百万输入 token 8 美元、输出 token 40 美元。它接收文字和图像，输出文字，可以结合工具完成编程任务。

这里展示的游戏场景和动画，是编程工作流交付的效果，不能据此把 Fable 5.2 当成一个直接输出视频的原生视频模型。本期也没有统计完整账单、生成耗时或帧率，所以先不谈成本和性能排名，重点看这次实际做出了什么。

## 从 Three.js 转向 Unity，这次想更贴近原画

[▶ 观看对应测试：00:25](https://www.youtube.com/watch?v=hA2FGW2HQww&t=25s)

之前用 Three.js 复刻的虹桥场景，单独看已经挺不错。但原画的味道很具体：桥怎么搭起来，房子是什么结构，人穿什么、站在哪里，都影响最后的感觉。只是有一座桥、一条河和几排房子，还不够。

这次我只给了一个很简单的要求，让它使用 Unity 3D 复刻《清明上河图》的虹桥部分。目标也更明确：尽量靠近原画的画风、建筑和人物特点。

需要说清楚的是，这不是一次只改变游戏引擎、其他条件全部相同的对照实验。本期没有严格控制所有变量，不能把最后的差异全部归功于 Unity。对我来说，更有价值的是看它能否把复杂的参考图拆开，再组织成一个可以探索的空间。

## 先从桥下穿过去，再回头看虹桥

[▶ 观看对应测试：01:32](https://www.youtube.com/watch?v=hA2FGW2HQww&t=92s)

进入场景时是鸟瞰视角，可以用键盘方向键移动。镜头不只停在一个漂亮的展示角度，我可以往桥底下钻，直接看桥的结构，也能穿过桥洞，在河道中加速移动。

这个观察方式很重要。如果只看远景，很多模型细节其实看不出来。到了桥下，再转向河岸，桥体、漕运船只和两侧建筑之间的关系就更清楚了。

上岸以后，还能调整到更高的角度看整体布局。在我的这次体验里，虹桥已经有了比较接近原画的感觉。不过这里的自由探索，主要是对场景和移动视角的展示，并没有完整测试碰撞、任务系统或一套正式游戏的玩法。

## 船只放倒桅杆过桥，是这次最有意思的一幕

[▶ 观看对应测试：02:13](https://www.youtube.com/watch?v=hA2FGW2HQww&t=133s)

靠近虹桥以后，先能看到桥上的人物。有人戴官帽，有人戴草帽、挑着东西停下来观看，不同人物有不同的装束、动作和表情。

接着就是船只过桥的场面。我把镜头靠近船，能看到桅杆慢慢放倒，桅杆上的绳索也比较清楚。船上的人有的拉绳，有的指挥，还有人在控制船的方向。

相比只摆一艘船在水面上，这些动作让场景多了一层过程感。观看的重点也从“这里有多少模型”，变成了“船正在做什么，周围的人为什么聚在这里”。

我在视频里觉得这艘船和画中已经比较接近，但这依然是视觉上的感受。人物动作和桥船细节是否符合真实漕运方式，还需要更专业的考证，不能把这次演示当成历史复原结论。

## 沿着河岸走，声音和小细节开始出现

[▶ 观看对应测试：03:01](https://www.youtube.com/watch?v=hA2FGW2HQww&t=181s)

把声音调大以后，能听到流水声、桥上类似人群交流的声音，还有鸟叫。镜头绕着船转一圈，再看桥下类似码头的那一小块区域，也有对应的场景细节。

接下来我往岸边的房子走。屋顶的瓦片比较清楚，旁边的树有随风摆动的效果。靠近树时，鸟叫声更明显，我还特意把音量调大，听了几种不同的叫声。

再往前，是挂着“十千脚店”招牌的店铺。旁边有白马和站着的人，路上有人抬轿子，也有人推着装货的车经过。原画里一个看起来像脚手架的结构，也被做进了场景，附近的酒旗还在风里飘。

我没有在这里给那个建筑下确定的名称，因为录制时也只是觉得它像脚手架。能做出来是一回事，具体是什么、用途是否准确，还得另外核对。

有一处两层房子，楼上坐着人。我把镜头移到二层，又绕到不同角度看房屋结构。靠近毛驴时还能听到叫声，这种跟探索位置联系起来的声音，让场景更有生活气息。

## 街巷里的人物，让场景不再只有建筑

[▶ 观看对应测试：04:57](https://www.youtube.com/watch?v=hA2FGW2HQww&t=297s)

继续往前，能看到挑着货物的人、两把大伞，还有坐在房子里的人。有人看起来像在喝茶，另几个人也像在吃东西或者喝茶，动作已经能表达出一种日常状态。

这里我更愿意保留“像在”这个说法。视频展示的是外观和动作，并没有去验证每个人物背后是否有独立的行为系统，更不能直接说已经做出一群会自主生活的 NPC。

回到桥附近，还能看到原画中的另一艘船，船上装着货物。这些散在河道、桥面和街边的细节拼起来，虹桥这一段的场面才逐渐完整。

我在视频里也提到，如果继续做精细打磨，应该还能更接近原画。现在让我满意的是，它已经把主要场景搭了起来，后面可以针对具体位置继续调整，而不是每次都从一个空场景开始。

## 回看 Claude Code，它先截取桥体，再给人物做标记

[▶ 观看对应测试：05:48](https://www.youtube.com/watch?v=hA2FGW2HQww&t=348s)

看完场景，我回到 Claude Code，翻了几个比较重要的处理步骤。

它会先围绕原画的局部做分析，例如截取桥的构造，再对桥进行复刻。人物部分也做了标记和编号，还能看到用绿色圆圈圈出人物头部的处理。

这一段让我觉得很值得看：我没有逐个告诉它桥上有哪些人、每个人应该放在哪里，它会自己先研究参考图，再推进还原。对于信息很密集的古画，光把图放大并不能让所有细节都变清楚，哪些地方能辨认、哪些地方需要补全，都会影响成品。

我当时给整体效果的主观评价是接近原画的七八成。**这不是图像相似度得分，也不是一套量化基准**，只是我对这一轮结果的观感。继续往下做，最值得检查的还是那些局部：桥体结构、人物位置、房屋比例，以及模型补出来的细节有没有偏离原画。

## 换一个尺度：Xeelee Ring 宇宙之环的建造动画

[▶ 观看对应测试：07:00](https://www.youtube.com/watch?v=hA2FGW2HQww&t=420s)

最后，我又让 Fable 5.2 复刻了一个科幻场景：斯蒂芬·巴克斯特 Xeelee 系列中的宇宙之环，也就是 Xeelee Ring 的建造过程。

这一段和虹桥的考验不太一样。虹桥有一张具体的原画可以对照，宇宙之环则更偏向把小说里的宏大构想做成能观看、能探索的动画场景。视频里我完整播放了这一段动画，整体观感很震撼，也可以继续进行探索。

不过，本期没有逐条核对小说设定，更没有验证物理尺度和工程过程。这里就把它当成一次科幻视觉化尝试，不把画面冲击力等同于科学准确性。

## 这次让我想继续试的，是把一张复杂参考图真正拆开

这次的重点，是从一幅很复杂的古画出发，做出桥、船、街巷、人物动作和环境声音，再允许我换角度去看这些东西。

最有价值的观察，一边在场景里：船只如何过桥，河岸上有哪些小细节；另一边在 Claude Code 的处理过程里：它怎样截取桥体、标记人物，再尝试把这些信息放回一个三维空间。

如果你也想做类似测试，我会建议先挑一小块信息丰富的区域，而不是一口气复刻整幅画。把同一处建筑和人物从几个角度看清楚，再检查移动、声音、碰撞和运行负担，最后决定要不要继续扩展。模型做出的第一版值得体验，但离可以直接交付的完整游戏，还有需要逐项验收的地方。

这轮结果让我觉得，虹桥这一段值得继续打磨。下一步比起再堆更多物体，我更想看局部能不能更准确，以及这些细节在长时间运行和不同设备上能否保持稳定。
