## 测试设置：统一 medium，但任务环境不同

本期在 Claude 网页端和 Claude Code 中都使用 medium 推理级别。前六项主要是网页端生成的单页作品；最后一项则进入 Claude Code，通过 Ultracode 工作流组织多智能体开发，使用 Unity 3D 和 C#。

这些条件必须放在结果前面。网页端生成一个可以打开的文件，与 Agent 在游戏工程中持续修改、构建和运行，是不同层次的测试。最后的成果也应归于模型、工作流和工具共同组成的开发环境，不能简单说成模型一次回答就生成了一款完整商业游戏。

Anthropic 的[官方发布说明](https://www.anthropic.com/claude-fable-and-mythos-5-1)确认了 Fable 5.1 这一模型名称及其面向编程、知识工作和复杂任务的定位。本文不照搬发布材料中的领先幅度，而是回到自己的案例。官方资料补充核对日期为 2026 年 10 月 24 日。

## 黑洞与住宅：空间效果和可探索性

[01:52，3D 黑洞](https://www.youtube.com/watch?v=P9Do94O6-8c&t=112s)这一题关注的是交互式呈现。生成的作品可以用鼠标旋转、缩放，查看吸积盘与整体形态，右侧还有参数控制。我的观感是画面很震撼，但视觉上接近电影镜头，不等于已经通过广义相对论数值计算的准确性验证。

[02:58，平面图转住宅](https://www.youtube.com/watch?v=P9Do94O6-8c&t=178s)则加入了图像输入。我提供室内平面图，要求生成可自由探索的 3D 空间，涵盖布局、墙体、门窗、家具和光照。

实际演示中，可以用方向键移动、鼠标转向，进入卧室、客厅、餐厅、厨房、卫生间和储物空间，也可以沿楼梯上到二层。沙发、电视、桌椅、灶台等细节都出现在场景里。这说明作品不只是一个外观模型，而是具备室内游走体验。不过，本期没有逐一测量墙体尺寸与原图误差，因此不能据此把它当作建筑建模精度测试。

## 南宋武侠游戏：多个玩法能否协同

[05:12 的武侠游戏](https://www.youtube.com/watch?v=P9Do94O6-8c&t=312s)以南宋临安为背景，玩家扮演白衣侠客，在古巷中活动并与黑衣刀客交战。

演示涉及攻击、切换招式、切换武器、飞行和进入建筑。场景里还有荷花池、室内人物、墙面字画，以及入夜后亮起的灯笼。这类任务比静态页面更考验系统之间的连接：人物控制、敌人、场景、时间变化需要同时工作。

本次短时间试玩可以支持“这些玩法已经出现在可运行版本中”，还不足以支持长时间稳定性、完整关卡设计或游戏平衡性的判断。

## 风洞与 SVG：交互模拟和动画各看什么

[07:01 的 F-35 数字风洞](https://www.youtube.com/watch?v=P9Do94O6-8c&t=421s)能够切换高速平飞、大攻角、接近失速等情景，并展示流线、速度云图、压力云图和粒子效果。视角可以旋转，面板参数随操作变化。

这是一项前端交互与科学可视化题。视频没有展示网格收敛、边界条件校验或与真实实验的对照，所以这里的“数字风洞”应理解为演示作品，而非可用于工程决策的 CFD 求解结果。

[08:36 的 SVG 动画](https://www.youtube.com/watch?v=P9Do94O6-8c&t=516s)要求几维鸟、渡渡鸟和鹈鹕在土星环上骑自行车比赛。它体现的是角色辨识度、骑行动作、星环构图和背景层次。相比只看画面是否精致，更值得观察的是多个指定对象有没有被遗漏，以及运动是否围绕同一个场景组织。

## 复活节岛石像：把研究题组织成连续过程

[09:28 的案例](https://www.youtube.com/watch?v=P9Do94O6-8c&t=568s)要求研究石像的开采、雕刻、运输与竖立，再用前端技术复现。

生成作品按阶段推进：从岩体上开采和雕刻，到利用绳索移动石像，再到安放于底座、处理帽状构件。演示还能切换视角，观察人物动作与环境光影。

这个例子说明模型能够把长流程组织为连续动画。至于每一步是否符合考古证据和物理约束，需要另行核对文献、工程参数与假设。动画完整、观感生动，与科研结论已经得到验证，是两件需要分别验收的事。

## Unity 3D 长任务：约三小时得到可运行沙盒

[12:25 开始的最后一项](https://www.youtube.com/watch?v=P9Do94O6-8c&t=745s)，我把此前使用 Godot 4 的沙盒游戏题改成 Unity 3D 与 C#，背景设为侏罗纪世界，并通过 Claude Code 配合 Ultracode 启动开发。

大约三小时后得到可运行版本。随后试玩中展示了恐龙、加特林射击、手雷、飞行、方块挖掘和放置，以及雨天、昼夜变化和闪电。可以创建世界、探索地形，再把这些机制串起来使用。

同时，视频保留了一个具体问题：进入水中后仍然显示雨效。因此不能把这次演示概括为“全部完美通过”。它提醒我们，生成可运行原型之后，还要继续检查场景状态、边界条件和视觉效果之间的关系。

## 两个 Max 20× 账号用尽，不能直接换算 API 成本

本轮测试合计用尽了两个 Claude Max 20× 账号当时可用的额度，这是原视频记录的使用经历。它不等于本期所有任务的精确 Token 数，也不能直接推出单个案例的美元成本，或者模型 API 单价一定高于另一款模型。

没有统一的输入输出统计、缓存信息和计费口径，就不应给出看似精确的成本结论。对准备复现的朋友来说，先选一个最相关的任务、保留工程检查点，再观察自己的额度与运行时间，更有实际意义。

这次最值得关注的提升，是复杂要求最终能变成可操作的作品；最需要保留的判断，是作品能运行之后，仍然需要验收。尤其涉及科学模拟、空间精度和长时间游戏运行时，不能只凭一段漂亮演示做结论。
