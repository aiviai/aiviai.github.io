个人 AI 助手真正需要解决的，往往不是一道更难的问答题，而是每天重复出现的小任务：筛选值得关注的项目、研究论文、把旧对话中的素材整理成能复用的笔记，以及在新需求到来时，不丢掉已经开始的工作。

这期 Claude Duet 的体验正好围绕这些问题展开。**最有价值的发现，不是“它比谁更强”，而是研究、整理、归档与任务切换可以放进同一套工作流。** 不过，一次录制中看到任务完成，仍然不等于它已经具备长期无人值守的可靠性。

## 先说清楚：Duet 是产品，不是另一个模型版本

Claude Duet 是 Anthropic 的主动型 Agent 产品。官方于 2026 年 10 月 21 日开放研究预览，强调它能够在独立云端计算机上继续处理任务，而不要求用户一直保持手机或电脑开启；其设计基于 **Claude Opus 5.5**。这不是本文独立验证的离线长程运行结果，而是官方产品定位。[官方发布说明](https://claude.com/resources/articles/claude-duet)

截至本文核查时，官方产品页仍标注美国 Pro、Max 用户通过候补名单获取研究预览资格，Team、Enterprise 暂未包含；后台检查与任务会消耗同一订阅的使用额度。**包含在订阅中不等于无限运行，也不等于人人已经能用。** 本文不推算每次研究的价格或 Token 成本，因为本期没有提供相应测量。[官方产品页](https://claude.com/product/claude-duet)

因此，理解这次体验可以先分开三个层面：Opus 5.5 是底层模型；Duet 是面向持续任务的产品入口；Notion、GitHub 研究与设计原型，则是实际工作流。把这三层混在一起，容易把某次界面演示误写成模型的通用能力。

## GitHub 研究：从一次回答变成可管理的任务

视频在 [02:16](https://www.youtube.com/watch?v=aQ8gC58O4l0&t=136s) 展示了一个 GitHub 研究频道。创作者希望它筛选 GitHub Trending 中与 AI 相关的项目，按价值排序，并为每个项目提供简短介绍。保存稿记录，输出把 Superpowers 放在第一位。

这里值得关注的是交互过程，而不是榜单第一名本身。在 [03:28](https://www.youtube.com/watch?v=aQ8gC58O4l0&t=208s) 开始的设置演示中，创作者通过自然语言提出目标，Duet 创建频道，再询问执行时间；随后手动要求立即运行，得到了一份项目整理结果。任务界面还提供立即运行、暂停、修改、重命名与执行历史等管理入口。

**已经得到支持的结论是：任务配置与一次即时运行形成了闭环。** 不能直接升级为“已经证明每天都能准点推送”。尤其是保存稿一处说选择早上 9 点，稍后又把界面中的下一次运行读作 8:47；由于本次无法复核对应画面，本文不把这段记录当作精确调度验证，也不擅自解释成时区问题或产品缺陷。

项目排序本身还有第二个验收点：它究竟是在按热度排序，还是按技术价值排序？本期没有逐项对照仓库证据，也没有给出完整评分复算。因此，最合理的定位是“研究助手交付的候选清单”，不是已经完成技术尽调的采购建议。

若把它用于日常工作，我建议额外规定：保留原始榜单顺序与仓库链接，区分代码、教程、索引和研究原型；许可证、发布版本、维护状态查不到时明确留缺口。以上是后续改进建议，不是本次已经执行的额外测试。

## 论文研究与 Notion：结果需要有落点

在 [05:09](https://www.youtube.com/watch?v=aQ8gC58O4l0&t=309s) 开始的部分，创作者连接 Notion，要求创建 AI 论文研究频道，并把研究结果保存进去。Duet 给出研究频率选项，创作者选择每天研究三篇。

保存稿记录，任务开始设置 Notion 数据库，随后输出论文研究内容，并在 Notion 中展示了三篇论文对应的记录。其中一篇被口述为与智能体工具调用训练有关。本文没有足够证据确认其准确论文名称、结论及引用完整性，所以不据此扩写研究成果。

这项体验说明的价值很具体：**信息发现与知识归档不再是完全断开的两步。** 对经常做研究笔记的人而言，减少复制粘贴、保持统一存放位置，可能比多生成一段摘要更有帮助。这是工作流分析，不是已测得的效率提升比例。

不过，“写进 Notion”与“研究正确”是两个验收标准。后续应抽查原论文链接、作者、版本、结论与局限是否被保留；还要检查相同论文再次出现时是否重复建档。三条记录的出现不能替代这些质量核查，也不能证明定时任务已经连续成功运行多天。

## 历史 Prompt 整理：并行体验最有说服力的一段

接下来的测试更贴近日常内容创作。在 [06:24](https://www.youtube.com/watch?v=aQ8gC58O4l0&t=384s)，创作者让 Duet 查找以前在 Claude 中使用的视频生成 Prompt，并整理到 Notion。

任务运行期间，又在 [07:18](https://www.youtube.com/watch?v=aQ8gC58O4l0&t=438s) 提交了第二个要求：创建汇总 Claude Code 新功能的频道，并立即运行。保存稿记载，新频道创建并输出更新后，原先的 Prompt 整理任务仍在推进；随后整理结束，创作者打开 Notion，看到带标题、描述和索引的笔记，并把任务标记完成。

这一段支持的判断，比泛泛的“支持多 Agent”更清楚：**在本次演示中，新增任务没有把先前任务直接打断，两个任务最终都产生了输出。** 这正是持续型个人助手需要解决的体验问题。

但“频道像子 Agent”“独立线程像进程”是帮助理解界面的类比，不是对底层进程隔离、并发架构或安全边界的技术证明。视频也没有提供精确并发数量、吞吐量或资源争用测量，不能把一次双任务演示外推成无限并行。

官方帮助页补充了一个重要边界：历史搜索覆盖 Duet 聊天和 Claude 中项目之外的聊天，并受相应搜索设置控制。因此，这不是“能看到账号里所有内容”的同义词。官方还说明，断开连接器会停止后续访问，但先前信息形成的记忆不会因此自动消失。[官方使用指南](https://support.claude.com/en/articles/17631495-get-started-with-claude-duet)

在真实使用中，最该继续验证的是整理的完整性：是否遗漏旧 Prompt、混入不相关内容、把不同版本合并，以及是否保留足够上下文。本文不会公开这次整理出的私人提示词或原会话。

## Claude Design：一个入口里交付原型，但不是生产应用验收

在 [08:34](https://www.youtube.com/watch?v=aQ8gC58O4l0&t=514s)，创作者从 Make 入口选择 Claude Design，要求生成现代化桌面登录页 Demo。保存稿记录，Duet 为它创建任务，随后展示登录页预览，创作者主观评价其外观美观，并标记完成。

这体现的是从提出需求到预览设计产物的路径。它不证明登录认证、账号系统、无障碍、移动适配或安全性已经实现。**好看的登录页原型与可上线的登录系统，仍然是两种交付物。** 本文没有复核实际画面，因而不增加关于配色、排版或动画质量的视觉评价。

后续浏览历史作品的片段，显示创作者可以从 Duet 入口找到之前的设计内容。这有利于理解“任务入口与产物入口集中”的体验，但不应把口述中的“所有功能打通”当成完整兼容性声明。官方限制仍然存在。

## 哪些能力还不能算测过

| 项目 | 本期证据 | 本文判断 |
| --- | --- | --- |
| GitHub 定时研究 | 配置任务、手动即时运行、查看管理入口 | 已展示流程；连续多日与准点执行未验证 |
| 论文及 Prompt 归档 | 保存稿记录 Notion 中的产物 | 支持归档体验；完整性与准确率未量化 |
| 多任务并行 | 新任务输出时旧任务继续，随后也完成 | 支持本次不中断体验；不构成通用并发基准 |
| Claude Design 登录页 | 原型生成、预览与创作者评价 | 不等于认证功能或生产质量验收 |
| 云端 Claude Code 交接 | 10:28 起向 Duet 提问，得到肯定回答 | 只是产品内回答，未演示真实交接与代码交付 |
| 语音交互 | 口述支持，并明确未演示 | 不报告识别、延迟或连续对话表现 |

原视频标题提出了与 Dots、Grok Bot、Meta Muse 的比较。保存稿也提到创作者先前使用 Grok Bot 时遇到任务被打断。但这些是不同时间、不同任务下的个人体验，不是同条件的系统对照试验。本文因此不宣布 Duet 已经全面超越其他产品。

## 更适合怎样开始使用

基于这期体验，我更建议把 Duet 的第一批任务限定在**低风险、能回读、便于人工检查的研究与整理工作**：先生成候选清单，再人工确认重要项目；先写入单独的测试笔记区，再核查归档质量；先同时执行两个可独立验收的任务，再观察任务状态与结果是否对应。

官方把发送消息、付款、签署和删除列为需要批准的行为，并承认研究预览仍可能误判信息。这里不应把“有审批”理解成绝对安全。敏感材料、对外发送与修改重要数据，应保留明确权限和人工复核。该建议不是对产品安全机制的独立渗透测试结论。

下一步最有价值的验证，不是继续堆叠演示数量，而是持续记录：任务是否按约定时间触发、失败是否被说明、重跑是否重复写入、报告有无来源、取消后是否真正停止，以及后台消耗是否影响正常使用额度。把这些记录保留下来，才能判断它是否值得从实验性助手进入日常工作。

## 结论

这次 Claude Duet 体验的核心，是把零散的任务组织成持续工作流：GitHub 项目研究有了固定频道，论文和历史 Prompt 有了 Notion 落点，新需求到来时，原任务没有在本次演示中被简单打断。

**它最值得关注的，是从“帮我回答”转向“帮我持续推进并留下可检查结果”。** 目前证据支持这一工作方式的初步可用性，而不是长期稳定性、研究正确率、无限并行或产品排名。对已经在 Claude 生态中积累了大量上下文的研究者、开发者和内容创作者，这是一条值得小范围验证的路径；对高后果操作，则仍需要明确授权、可回读的结果和人工判断。
